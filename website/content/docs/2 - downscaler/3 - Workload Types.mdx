# Workload Types

Valid values for the workload type are the case-insensitive Kubernetes resource names of the workloads.
Workload types to be included in the scaling process can be specified using the
[`--include-resources`](ref:docs-runtime-configuration#include-resources) argument at the [CLI Scope](ref:docs-cli-scope#runtime-configuration)

## List of Workload Types

Here is a list of all the workload types supported by KubeDownscaler and how they are scaled.

### Cronjobs

- id: cronjobs
- resource: cronjob.v1.batch

Scales by setting the cronjobs suspend property to true, which halts further scheduled runs of the Cronjob.

### Daemonsets

- id: daemonsets
- resource: daemonset.v1.apps

Scales by setting the node selector to match none of the nodes, which stops pods from running on any node.

### Deployments

- id: deployments
- resource: deployment.v1.apps

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### HPAs

- id: horizontalpodautoscalers
- resource: horizontalpodautoscaler.v2.autoscaling

Scales by setting the minReplicas to the [downscale replicas](ref:docs-values#downscale-replicas).
If the [downscale replicas](ref:docs-values#downscale-replicas) are less than 1 it will throw an error.
When restoring the original minReplicas value, if minReplicas happens to be greater than the current maxReplicas value,
the downscaler will set minReplicas to the current maxReplicas value to avoid configuration errors.

### Jobs

- id: jobs
- resource: job.v1.batch

Scales by setting the suspend property to true, which stops the execution of the job until it is upscaled again.

### PodDisruptionBudgets

- id: poddisruptionbudgets
- resource: poddisruptionbudget.v1.policy

Scales by setting the maxUnavailable or minAvailable properties (depending on which one is used) to the
[downscale replicas](ref:docs-values#downscale-replicas).
[Percentage values](ref:docs-replicas#syntax) are supported as well

### ScaledObjects

- id: scaledobjects
- resource: scaledobject.v1alpha1.keda.sh

Scales by setting the paused replicas annotation to the [downscale replicas](ref:docs-values#downscale-replicas),
which scales the workloads managed by the scaled object to the [downscale replicas](ref:docs-values#downscale-replicas).

When scaled objects are [being scaled](ref:docs-runtime-configuration#include-resources) the downscaler will
automatically exclude the workloads the scaled objects are managing to avoid conflicts.

### Statefulsets

- id: statefulsets
- resource: statefulset.v1.apps

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### Rollouts

- id: Rollouts
- resource: rollout.v1alpha1.argoproj.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### Stacks

- id: stacks
- resource: stack.v1.zalando.org

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### Prometheuses

- id: prometheuses
- resource: prometheus.v1.monitoring.coreos.com

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### AutoscalingRunnerSets

- id: autoscalingrunnersets
- resource: autoscalingrunnerset.v1alpha1.actions.github.com

Scales by setting the minRunners count to the [downscale replicas](ref:docs-values#downscale-replicas).

### Services

- id: services
- resource: services.v1

Scales by setting the type to ClusterIP.

### AWSELBServices

- id: awselbservices
- resource: services.v1

Scales by setting the type to ClusterIP.
Only services without the `service.beta.kubernetes.io/aws-load-balancer-type` annotation or
with the `service.beta.kubernetes.io/aws-load-balancer-type` annotation set to a value different from `nlb` are scaled.

### AWSNLBServices

- id: awsnlbservices
- resource: services.v1

Scales by setting the type to ClusterIP.
Only services with the `service.beta.kubernetes.io/aws-load-balancer-type` annotation
set to `nlb` are scaled.

### Ingresses

- id: ingresses
- resource: ingresses.v1.networking.k8s.io

Scales by setting the IngressClassName of the Ingress object to `downscaler-ingress-class`.
In a constrained installation, the IngressClass object with the name `downscaler-ingress-class` must
be provisioned by a cluster administrator having the necessary cluster-wide permissions

### Gateways

- id: gateways
- resource: gateway.v1.networking.k8s.io

Scales by setting the GatewayClassName of the Gateway object to `downscaler-gateway-class`.
In a constrained installation, the GatewayClass object with the name `downscaler-gateway-class` must
be provisioned by a cluster administrator having the necessary cluster-wide permissions

## Operator Custom Resources vs. Their Workloads

The data-engine types below scale the operator's custom resource, not the ReplicaSet or StatefulSet the operator manages.
This covers the Postgres, CNPG, RabbitMQ, Elasticsearch, MongoDB, Redis, and Kafka kinds listed below.
The downscaler patches the CR and the operator reconciles its own StatefulSets from that change.

The generic `statefulsets` scaler is deliberately kept off StatefulSets owned by these operators.
Any StatefulSet whose controller owner-reference is one of these kinds (matched by API group and kind) is excluded from the generic pass.
Do not add both a data engine's CR and its StatefulSet to `--include-resources`, or the two scalers fight over the same workload.
Enable a data engine by including only its CR type.

Some operators do not scale their own workloads down.
Elasticsearch's `pause-orchestration` stops reconciliation without stopping pods.
The MongoDBCommunity operator short-circuits once `members` is 0.
For those the CR scaler also scales the child StatefulSets itself, gated by [downscaler/scale-children](ref:docs-values#scale-children).

The RabbitMQ, CNPG, Elasticsearch, MongoDB and Redis kinds are not compiled in.
They are [workload definitions](#workload-definitions) shipped as chart defaults, so they can be changed,
removed or joined by other operators through Helm values alone.

### Postgresqls

- id: postgresqls
- resource: postgresql.v1.acid.zalan.do

Scales by setting the numberOfInstances count to the [downscale replicas](ref:docs-values#downscale-replicas).

### RabbitmqClusters

- id: rabbitmqclusters
- resource: rabbitmqcluster.v1beta1.rabbitmq.com

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).
Requires the [RabbitMQ Cluster Operator](https://github.com/rabbitmq/cluster-operator).
The operator supports `replicas: 0` natively and records the previous count in `rabbitmq.com/before-zero-replicas-configured`.
It only accepts that count when scaling back up, so that is the value the downscaler restores.
The StatefulSet the operator creates is owned by the RabbitmqCluster and is left alone.

### CnpgClusters

- id: cnpgclusters
- resource: cluster.v1.postgresql.cnpg.io

Suspends by setting the operator's `cnpg.io/hibernation` annotation to `on`, and resumes by setting it to `off`.
Requires the [CloudNativePG operator](https://github.com/cloudnative-pg/cloudnative-pg).
On the way down the operator deletes the instance pods (replicas first, primary last) but keeps the PVCs, so data survives.
On the way up it recreates the pods.
This is a suspend-shaped workload, not a replica-shaped one: the operator owns the count and the downscaler only toggles hibernation.

### Elasticsearches

- id: elasticsearches
- resource: elasticsearch.v1.elasticsearch.k8s.elastic.co

Suspends by setting the `eck.k8s.elastic.co/pause-orchestration` annotation to `true`, and resumes by setting it to `false`.
Because pausing does not stop the node pods, the scaler also scales the cluster's node-set StatefulSets to 0 (its children),
matched by the `elasticsearch.k8s.elastic.co/cluster-name` label; ECK restores them on wake.
Requires [downscaler/scale-children](ref:docs-values#scale-children) to be enabled.

### MongoDBCommunities

- id: mongodbcommunities
- resource: mongodbcommunity.v1.mongodbcommunity.mongodb.com

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).
Requires the [MongoDB Community Kubernetes Operator](https://github.com/mongodb/mongodb-kubernetes-operator).
Refuses to park a resource lacking the `mongodb.com/v1.lastSuccessfulConfiguration` annotation;
the operator would have no known-good config to restore.

### RedisReplications

- id: redisreplications
- resource: redisreplication.v1beta2.redis.redis.opstreelabs.in

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas) via `spec.clusterSize`.
Requires the [Redis Operator by OpsTree Labs](https://github.com/OT-CONTAINER-KIT/redis-operator).

### RedisSentinels

- id: redissentinels
- resource: redissentinel.v1beta2.redis.redis.opstreelabs.in

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas) via `spec.clusterSize`.
Requires the [Redis Operator by OpsTree Labs](https://github.com/OT-CONTAINER-KIT/redis-operator).
The CRD forbids a `clusterSize` of 0, so the CR is floored at 1 and the sentinel StatefulSet (owned by the RedisSentinel)
is scaled to 0 as a child.
Requires [downscaler/scale-children](ref:docs-values#scale-children) to be enabled.

### KafkaConnects

- id: kafkaconnects
- resource: kafkaconnect.v1.kafka.strimzi.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).
Requires the [Strimzi Kafka Operator](https://strimzi.io/) `>=0.49` (the `v1` API was introduced in 0.49 and
the legacy `v1beta2` was removed in 1.0.0).

### KafkaMirrorMaker2s

- id: kafkamirrormaker2s
- resource: kafkamirrormaker2.v1.kafka.strimzi.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).
Requires the [Strimzi Kafka Operator](https://strimzi.io/) `>=0.49` (the `v1` API was introduced in 0.49 and
the legacy `v1beta2` was removed in 1.0.0).

### KafkaBridges

- id: kafkabridges
- resource: kafkabridge.v1.kafka.strimzi.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).
Requires the [Strimzi Kafka Operator](https://strimzi.io/) `>=0.49` (the `v1` API was introduced in 0.49 and
the legacy `v1beta2` was removed in 1.0.0).

### KruiseStatefulSets

- id: advancedstatefulsets
- resource: statefulset.v1beta1.kruise.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### CloneSets

- id: clonesets
- resource: clonesets.v1beta1.kruise.io

Scales by setting the replica count to the [downscale replicas](ref:docs-values#downscale-replicas).

### BroadcastJobs

- id: broadcastjobs
- resource: broadcastjobs.v1beta1.kruise.io

Scales by setting the suspend property to true.

:::warning
According to Kruise documentation, this won't stop the job from running,
but it will prevent new pods from being created.
:::

### ImagePullJobs

- id: imagepulljobs
- resource: imagepulljobs.v1beta1.kruise.io

Scales by setting the suspend property to true.

:::warning
According to Kruise documentation, this won't stop the job from running,
but it will prevent new pods from being created.
:::

### AdvancedCronJobs

- id: advancedcronjobs
- resource: advancedcronjobs.v1beta1.kruise.io

Scales by setting the suspend property to true, which halts further scheduled runs of the AdvancedCronJob.

### AdvancedDaemonSets

- id: advanceddaemonsets
- resource: advanceddaemonsets.v1beta1.kruise.io

Scales by setting the node selector to match none of the nodes, which stops pods from running on any node.

## Workload Definitions

Operator custom resources that are scaled by one value can be described in configuration instead of code.
The chart's `workloadDefinitions` value is rendered into a ConfigMap, mounted into the downscaler and the webhook,
and loaded at startup from [`--workload-definitions-file`](ref:docs-runtime-configuration#workload-definitions-file)
(default `/etc/downscaler/workload-definitions.yaml`).
The same value generates the RBAC rules, webhook rules and admission-policy rules, so they cannot drift apart.
Changing a definition rolls the pods through a checksum annotation.

A definition is only used for resources listed in [`--include-resources`](ref:docs-runtime-configuration#include-resources).
An invalid definition, or an included resource that is neither built in nor defined, stops the downscaler at startup
so a bad values change fails the rollout instead of silently skipping workloads.

### Schema

Each key of `workloadDefinitions` is the resource name used in `--include-resources`.
It must be lowercase and must not be a built-in resource.

| Field                                              | Required                      | Description                                                                                                                                                                                                                                |
| -------------------------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `group`, `version`, `kind`                         | yes                           | The custom resource's API group, version and kind.                                                                                                                                                                                         |
| `plural`                                           | no                            | The CRD's plural resource name, used for RBAC and admission rules. Defaults to the key.                                                                                                                                                    |
| `replicas.path`                                    | one of `replicas` / `suspend` | Dot-separated path to an integer replica field.                                                                                                                                                                                            |
| `replicas.minimum`                                 | no                            | Downscale targets below this are clamped to it. Default 0.                                                                                                                                                                                 |
| `suspend.annotation` or `suspend.path`             | one of `replicas` / `suspend` | The annotation, or a dot-separated path to a spec field, that suspends the resource.                                                                                                                                                       |
| `suspend.suspendedValue`, `suspend.resumedValue`   | with `suspend`                | The values that mean suspended and resumed. A missing annotation or field reads as resumed. For a field, `"true"` and `"false"` are written as booleans.                                                                                   |
| `parkGuard.requireAnnotations`                     | no                            | Replica-shaped only. Scaling to 0 is refused unless every listed annotation is present. Partial downscales and scale-ups are never blocked.                                                                                                |
| `children[].kind`                                  | no                            | `StatefulSet` or `Deployment` workloads scaled to 0 with the parent when [downscaler/scale-children](ref:docs-values#scale-children) is enabled.                                                                                           |
| `children[].match`                                 | with `children`               | `ownerReference` (an owner reference to the parent's group, kind and name) or `labelEqualsName` (the `label` equals the parent's name).                                                                                                    |
| `children[].label`                                 | with `labelEqualsName`        | The label key to match.                                                                                                                                                                                                                    |
| `savings.requestsPath` or `savings.containersPath` | no                            | Where one pod's resource requests live, for the saved-resources metric: a requests map, or a container list whose requests are summed. Without `savings` the metric reports 0 for the kind.                                                |
| `savings.countPath`, `savings.groupsPath`          | no                            | Suspend-shaped only. `countPath` is the number of pods (default 1). With `groupsPath`, the other paths are relative to each item of that list and the results are summed. Replica-shaped kinds multiply by the change in replicas instead. |

### Example

The chart ships the RabbitMQ, CNPG, Elasticsearch, MongoDB and Redis kinds as defaults; see `workloadDefinitions` in the chart's
`values.yaml` for all of them.
Two of them show the shapes:

```yaml
workloadDefinitions:
  mongodbcommunities:
    plural: mongodbcommunity
    group: mongodbcommunity.mongodb.com
    version: v1
    kind: MongoDBCommunity
    replicas:
      path: spec.members
    parkGuard:
      requireAnnotations:
        - mongodb.com/v1.lastSuccessfulConfiguration
    children:
      - kind: StatefulSet
        match: ownerReference
    savings:
      containersPath: spec.statefulSet.spec.template.spec.containers
  cnpgclusters:
    plural: clusters
    group: postgresql.cnpg.io
    version: v1
    kind: Cluster
    suspend:
      annotation: cnpg.io/hibernation
      suspendedValue: "on"
      resumedValue: "off"
    savings:
      requestsPath: spec.resources.requests
      countPath: spec.instances
```

Set a key to `null` to drop a default, and add `includedResources` entries for the definitions you want scaled.

### Adding an Operator

1. Find the one value that parks the resource.
   If it is an integer count, the definition is replica-shaped.
   If it is a flag or annotation that the operator honours, it is suspend-shaped.
2. Check whether the operator keeps pods running after that change, as ECK does when paused or the MongoDB operator does at 0 members.
   If it does, add `children` so the downscaler scales the StatefulSets or Deployments itself.
3. Check whether the operator can recover from a park in any state.
   If not, add a `parkGuard` for the annotation that marks a safe state.
4. Check whether the CRD forbids 0.
   If it does, set `replicas.minimum` and let a child carry the park.
5. Add the key to `includedResources` and roll out.
   The downscaler logs `loaded workload definitions` with the registered resources.

Anything that cannot be expressed this way still needs a scaler in code, as the built-in types above do.
